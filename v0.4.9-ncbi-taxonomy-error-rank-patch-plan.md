## 3. Required behavior contracts

### 3.1 Classify outcomes explicitly

Replace the overloaded `(taxid, error, ambiguous_taxids)` contract with a typed outcome or clearly documented equivalent. Suggested statuses:

- `resolved`: exact accepted name, compatible rank, valid ordered ancestry.
- `not_found`: valid ESearch response with zero results.
- `ambiguous`: multiple candidate IDs; never select the first silently.
- `context_mismatch`: valid record with wrong scientific name, incompatible rank, missing ancestor, repeated ancestor ambiguity, or wrong ancestry order.
- `request_failed`: exhausted transport/service failure, or permanent HTTP failure.
- `response_invalid`: malformed JSON/XML, missing required fields, explicit API error payload, or response TaxID inconsistent with the requested record.

Never interpret missing `esearchresult`/`idlist` as a valid zero-hit response. Check declared result count against returned IDs where needed so truncated candidate lists cannot masquerade as uniqueness. Preserve current conservative ambiguity behavior; candidate disambiguation is deferred.

`request_failed` and `response_invalid` are fatal under both policies and both full-resolution modes. `not_found`, `ambiguous`, and `context_mismatch` remain unresolved: warn and report under `warn`; fail under `error`. This is an intentional behavior change for semantic mismatches and must be documented. A mismatch never inserts a positive cache entry.

Maintain `query_failures` in provenance for true request/response failures; add a separate mismatch collection. Check exact-schema consumers and release verification before adding fields. If strict consumers require a provenance version change, update producers, validators, and fixtures together.

### 3.2 Accept narrowly scoped domain compatibility

Support the legacy `superkingdom` and current `domain` spellings for the canonical cellular roots Bacteria, Archaea, and Eukaryota. Maintain the existing output rank conventions unless a separate output-schema migration is needed; accepting an NCBI source rank must not silently change Kraken rank codes or lineage depth.

Keep strict scientific-name and ordered-ancestry checks. Do not allow arbitrary ranks at depth 1; do not generalize the alias to Viruses, realm, acellular root, cellular root, or an arbitrary named taxon. Preserve exact-rank matches for all other cases. Record expected and returned rank and the compatibility rule used when an alias was needed.

### 3.3 Preflight semantics

| Invocation | Network behavior | Result contract |
| --- | --- | --- |
| Cache-only validation | No requests | Evaluate unresolved policy against available local evidence. |
| Refresh validation, no online flag | No requests | Validate local inputs/credentials and report pending resolution. Do not claim taxonomy is fully resolved. |
| Refresh validation + explicit online flag | Full resolution, read-only | Same outcome/policy decisions as real execution; no cache/output/log-file mutation. |
| Normal refresh execution | Local preflight, then one real resolution pass | Commit only after the existing transaction gates succeed. |

For local refresh validation, unresolved-policy `error` is deferred until resolution, since network work has intentionally not occurred. Emit a machine-readable/text summary such as `taxonomy_resolution=pending_online`, with pending node count; preserve the distinction from successful full online validation in the R validation summary.

If `--online-preflight` is supplied without top-level `--validate-only`, fail early with a clear instruction to remove it or run a separate explicit validation command. This avoids silently ignoring a requested operation or retaining the duplicate-pass footgun. Update CLI help and README accordingly. A user who deliberately runs full online validation and then a separate execution is choosing two passes; no hidden cache writes should be introduced to avoid that.

### 3.4 Durable diagnostics, transactional results

Keep published scientific outputs and the authoritative taxonomy cache transactional. Failed runs must not expose a candidate cache as successfully committed.

Use a run-specific diagnostics directory outside both final scientific outputs and disposable module/run staging, for example a uniquely created sibling directory under `<output-parent>/.wf16s-diagnostics/`. Associate it with run/transaction identity. Validate destination containment, avoid existing files/symlinks, and never put diagnostic files inside the stage census.

Create this only for actual execution. Validate-only must remain filesystem-mutation-free. Its diagnostics go to stderr/stdout only; shell redirection is an external caller action.

Persist a bounded structured event stream and final failure summary. Include code, phase, lookup identity, attempt, elapsed time, completed/total count, and safe explanation. Flush start/progress/retry/failure events; report progress periodically even during slow request sequences. A bounded network timeout still determines how quickly a stuck request can emit its next event.

Never log API keys, contact-email values, raw credential-bearing URLs, environment dumps, or unrestricted exception strings. Scientific names/context may be logged as taxonomy evidence, but no read sequences. Redact before writing, not after the file exists. Report the diagnostics path in the R error.

Avoid describing every failure as a network failure. Example:

```text
E_TAXONOMY_CONTEXT: expected species, returned genus; node left unresolved
E_NCBI_REQUEST: efetch exhausted 3 attempts; HTTP 503
E_NCBI_RESPONSE: missing esearchresult.idlist
```

Preserve cache hashes, existing lock ownership, deferred commit, rollback/recovery behavior, and failed-module empty-output contracts. Diagnostics are operational evidence, not successful module artifacts.

### 3.5 Retry boundaries and stopping

Apply a shared monotonic request limiter before every ESearch/EFetch attempt. Preserve conservative intervals of at least 0.35 s without a key and 0.12 s with a key; document that multiple processes/IP-sharing clients require coordination. Do not add a worker pool here.

Retry transient transport failures and HTTP 429/appropriate 5xx responses with bounded backoff, honoring a bounded `Retry-After`. Fail immediately for permanent HTTP failures and malformed/semantically invalid payloads unless a documented reason justifies a retry. Retry EFetch itself without repeating a successful ESearch.

Once a fatal lookup outcome is known, stop issuing further lookups, persist evidence, and fail. Semantic unresolved outcomes continue so `warn` can complete useful work. Never retry KeyboardInterrupt/SystemExit. Keep logs usable when interruption prevents the final summary; flushed events should already exist.

Use managed process-tree cleanup for R/Python children and test on Windows and Linux. Do not claim a child can guarantee cleanup when an unrelated outer controller is force-killed. Document the supported supervisor/cancellation behavior and the residual limitation of hard OS termination.

## 6. Required regression matrix

All network-facing tests use mocked responses; fixtures must not include real credentials.

| Test | Expected result |
| --- | --- |
| Timeout in full online preflight, policy warn/error | Nonzero for both; same fatal code as execution; source cache unchanged. |
| HTTP 429/503 followed by success | Bounded retry, limiter applied on each attempt, safe retry event. |
| HTTP 400/401/403 | No blind repeated requests; clear permanent failure. |
| EFetch transient failure after successful ESearch | One ESearch; retry only EFetch. |
| Missing/malformed ESearch fields or API error JSON | Fatal response_invalid, never not_found. |
| Missing/wrong EFetch TaxID, malformed XML | Fatal response_invalid; no positive cache insertion. |
| Bacteria, Archaea, Eukaryota returned as domain with expected superkingdom | Accepted with alias provenance; scientific name and ancestry still checked. |
| Legacy exact superkingdom and all existing exact ranks | Continue to pass. |
| Species returned as genus; unknown taxon with domain alias; viral realm/acellular root | Alias does not bypass rejection. |
| Missing/reversed/duplicate ancestor or mismatched scientific name | Remains rejected; warn leaves unresolved; error fails. |
| Semantic mismatch followed by another resolvable key | Warn completes and records both correctly. |
| Fatal request failure early in list | No later lookups; nonzero; diagnostics explain incomplete work. |
| Cache-only validation/execution | Zero network calls; policy unchanged. |
| Local refresh validation with unresolved-policy error | Zero requests/writes, explicit pending_online, not falsely fully resolved. |
| Normal refresh run | Zero preflight HTTP requests; one execution resolution pass. |
| Explicit online-preflight without top-level validate-only | Early usage error, no mutation/network. |
| Validation-only filesystem snapshot | No new files, cache changes, diagnostic directory, or publication. |
| Forced module failure and normal cleanup | Diagnostic events survive; final output absent or prior final unchanged; source cache restored/unchanged. |
| Downstream failure after taxonomy candidate creation | Existing rollback and transaction journal tests still pass. |
| Error message containing fake API key/email/URL | Secrets absent from stderr, logs, JSON, and R error. |
| Windows/Linux supervised cancellation | No surviving managed resolver child; no partial publication; prior flushed log remains. |

## 8. Acceptance criteria and final handoff report

The patch is ready for review when:

- Full online validation never succeeds on fatal request/response errors that execution rejects.
- Current cellular domain records pass the narrow compatibility rule; unrelated rank/name/ancestry mismatches remain unresolved or fatal according to the explicit policy.

- Failure evidence survives ordinary staging cleanup and contains no credentials.
