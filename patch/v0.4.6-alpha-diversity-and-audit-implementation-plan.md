## 1. Executive decision

Astra’s recommendation is correct: the repository is not release-ready for `v0.4.6`.

The most immediate hard failure is the Linux Krona vendor-integrity check. The committed `LICENSE.txt` is LF-only, while `analysis/vendor/krona-2.8.1/SOURCE.json` contains the SHA-256 for the CRLF representation. The current Python validation run therefore fails before rendering. This must be repaired and tested from fresh Linux and Windows checkouts.

The remaining release risks are correctness risks rather than cosmetic cleanup:

1. Display-label validation can rebuild labels from a filtered selected-taxa table and miss collisions that exist in the authoritative rank table.
2. The release verifier checks Krona arithmetic but does not prove that HTML taxonomy, direct counts, and TSV taxonomy/counts are the same data.
3. The composition verifier partly verifies values produced by the same code path rather than independently recomputing from source counts; unequal-depth samples are not protected against pooled-count mistakes.
4. Transaction recovery can release locks before rollback completes, remove recovery material after a failed cleanup, and leave taxonomy state out of sync with a published output. Journals have no shared run/transaction identity.
5. The R/Python taxonomy-cache lock boundary relies on different native locking mechanisms and needs an explicit interoperability test.

The alpha-diversity request should be implemented as a contract extension to the existing rarefaction-resample workflow. The current `02b_resample_boxplots.png` represents distributions across repeated rarefactions at one standardized read depth; it is not a biological-replicate boxplot. That subtitle and provenance must remain explicit.

## 3. Alpha-diversity contract to implement

### 3.1 Data and denominator rules

- Continue excluding the `Unclassified` row from alpha metrics.
- Use classified reads as the denominator for proportions and all count-based alpha estimates.
- Keep counts as genuine non-negative integers before calling count-based estimators.
- Keep the existing rarefaction design: without-replacement resampling, one common realized depth, deterministic per-sample seeds, and `NA` plus a structured reason for undefined metrics.
- A rarefaction-resample observation is a sensitivity replicate, not a biological replicate. Do not use those rows as independent observations in group tests.
- Preserve the existing full-depth output and existing column order; append new stable keys so downstream consumers remain readable.
- Do not convert a zero-classified sample to 100% `Other`. Preserve the current eligibility gate and explicit undefined/skip semantics.

The canonical plot input should become a long table with at least:

`SampleID`, `iteration`, `subsample_depth`, `MetricKey`, `MetricLabel`, `Parameter`, `Value`, `Valid`, `Reason`.

The existing wide `rarefaction_resamples.tsv` should remain available with its current columns first and new columns appended in registry order. The long table prevents parameterized Hill/Rényi metrics from being mistaken for one unparameterized value.

### 3.2 Metric registry and definitions

Implement one registry in `analysis/utils/metrics.R` (or a dedicated `alpha_metrics.R`) and use it for calculation, labels, output schemas, and plots. Record the formula, package/method, parameter, valid domain, and undefined rule in `alpha_metric_definitions.tsv`.

| Figure | Stable key / display label | Definition and implementation rule |
|---|---|---|
| 1 | `richness` / Richness (S) | Number of taxa with positive count. Existing metric. |
| 1 | `shannon` / Shannon (H) | `H = -sum(p_i * log(p_i))`. Existing `vegan::diversity(..., index="shannon")`. |
| 1 | `ens` / ENS (e^H) | `exp(H)`. Existing metric. |
| 1 | `simpson` / Simpson (D) | Preserve current semantics: `1 - sum(p_i^2)`, not the reciprocal. |
| 1 | `invsimpson` / Inv. Simpson | `1 / sum(p_i^2)`. |
| 1 | `fisher_alpha` / Fisher's alpha | `vegan::fisher.alpha()` on genuine integer counts; return `NA` with a reason if no valid solution exists. |
| 2 | `chao1` / Chao1 | `vegan::estimateR(counts)["S.chao1"]`; retain existing behavior and provenance. |
| 2 | `ace` / ACE | `vegan::estimateR(counts)["S.ACE"]`; document the estimator’s rare-abundance threshold and count requirement. |
| 2 | `pielou` / Pielou's evenness (J) | `H / log(S)` for `S > 1`; undefined otherwise. |
| 2 | `berger_parker` / Berger-Parker index | Preserve the requested dominance form `max(n_i) / N`; do not silently report its reciprocal. |
| 3 | `heip` / Heip's evenness | `(exp(H) - 1) / (S - 1)` for `S > 1`; undefined otherwise. |
| 3 | `evar` / Smith-Wilson Evar | For positive taxa, `1 - (2/pi) * atan((1/S) * sum((log(n_i) - mean(log(n)))^2))`. Document the selected single-taxon rule and test it; recommended release rule is `NA` for non-informative `S <= 1`. |
| 3 | `mcintosh` / McIntosh diversity index | `D_Mc = (N - sqrt(sum(n_i^2))) / (N - sqrt(N))` for `N > 1`; label as diversity, not evenness. |
| 3 | `renyi_q1` / Rényi entropy (q=1) | `H_q = log(sum(p_i^q))/(1-q)` for `q != 1`, with the Shannon limit at `q=1`. The default plot uses `q=1` and labels the order explicitly. |
| 4 | `hill_q0`, `hill_q1`, `hill_q2` / Hill number (q=0/1/2) | `N_q = exp(H_q)`: q=0 is S, q=1 is ENS, and q=2 is inverse Simpson. Keep all three as separate facets because they have different orders but compatible “effective taxa” interpretation. |
| 4 | `faith_pd` / Faith's Phylogenetic Diversity | Sum of branch lengths in the minimal rooted subtree connecting observed taxa; requires a rooted tree with branch lengths. |
| 4 | `psr` / Phylogenetic Species Richness (PSR) | `PSR = PSV * S`, with PSV computed from the phylogenetic covariance/VCV matrix. Presence/absence only. |
| 4 | `pse` / Phylogenetic Species Evenness (PSE) | Abundance-weighted phylogenetic evenness using the same species-by-tree mapping; undefined for fewer than two observed taxa. |

The formula choices align with the current `vegan` definitions for diversity, Fisher alpha, and Rényi/Hill relationships; see the [vegan diversity documentation](https://vegandevs.github.io/vegan/reference/diversity.html) and [vegan Rényi documentation](https://vegandevs.github.io/vegan/reference/renyi.html). Smith-Wilson Evar, ACE, Berger-Parker, and Hill conventions should be cross-checked against the [Bioconductor mia alpha-index documentation](https://microbiome.github.io/mia/reference/addAlpha.html). PSR/PSE and Faith PD should follow the pinned implementation and definitions in [picante’s phylogenetic-diversity source](https://github.com/skembel/picante/blob/master/R/phylodiversity.R) and [PD documentation](https://github.com/skembel/picante/blob/master/man/pd.Rd).

### 3.3 Parameter and phylogeny rules

1. Add `alpha$hill_orders`, defaulting to `c(0, 1, 2)`. Never combine multiple orders under a single unlabeled “Hill numbers” facet.
2. Add `alpha$renyi_orders`, defaulting to `c(1)`. If users request additional orders, emit one key/facet per order or a separate profile figure; never mix orders on one y-axis.
3. Add an optional `input$phylogenetic_tree` path. Require a rooted Newick tree with unique tip labels, non-negative branch lengths, and no silent branch-length imputation.
4. Because the current abundance rows are canonical taxonomy paths rather than a guaranteed feature identifier, add an optional `input$phylogenetic_tip_map` TSV with a unique `TaxonPath` → `TipLabel` mapping. If no map is supplied, require exact tip/path identity. Every positive classified taxon used for a phylogenetic metric must map; unmapped taxa are a validation error or an explicit module skip, never silently dropped.
5. `Unclassified` must never be mapped to a phylogenetic tip. Extra tree tips may be pruned, but the manifest must record that fact.
6. Prefer an optional, pinned `picante` dependency for PD/PSR/PSE because `ape` is already locked but `picante` is not a top-level locked dependency. Load it only when a valid tree is requested; record package versions in provenance. If formulas are implemented in-house instead, add fixture-level equivalence tests against pinned `picante` results before release.

If the user intended one scalar Hill number rather than the scientifically standard q=0/1/2 profile, make the order an explicit configuration choice. The default four-plot layout below uses three Hill facets so the fourth PNG contains six sections.

## 4. PNG output contract

The first requested figure is the only figure that can be data-backed from the current checkout without a phylogenetic tree. The attached preview `alpha-diversity-first-boxplot-preview.png` uses the repository’s Ambar abundance counts and a deterministic rarefaction recreation; it is a layout/data preview, not a replacement for the R pipeline output. The implementation should generate the final figures from the canonical long resample table.

| Output | Required facets, in fixed order | Layout |
|---|---|---|
| `02b_resample_boxplots.png` | Richness (S), Shannon (H), ENS (e^H), Simpson (D), Inv. Simpson, Fisher's alpha | Six facets; two rows; free y scales; preserve the existing file name. |
| `02c_resample_boxplots_estimators_evenness.png` | Chao1, ACE, Pielou's evenness (J), Berger-Parker index | Four facets; two rows; free y scales. |
| `02d_resample_boxplots_evenness_entropy.png` | Heip's evenness, Smith-Wilson Evar, McIntosh diversity index, Rényi entropy (q=1) | Four facets; two rows; free y scales. |
| `02e_resample_boxplots_phylogenetic.png` | Hill number (q=0), Hill number (q=1), Hill number (q=2), Faith PD, PSR, PSE | Six facets; two rows; only when the phylogeny contract is satisfied. |

All figures should:

- state standardized depth, iteration count, seed policy, and “rarefaction sensitivity, not biological replication” in the subtitle or sidecar metadata;
- use deterministic sample/facet ordering from the metric registry;
- use free y scales because the metrics have incompatible units/ranges;
- hide a facet only when its metric is explicitly ineligible, and never replace missing phylogenetic data with a fabricated value;
- emit a structured `alpha_phylogeny_skipped.tsv` when the optional tree is absent or invalid, with status, reason, input paths/hashes, and affected metrics; and
- use a fixed image size/DPI and a deterministic plot theme so image hashes are stable for identical inputs.

The release manifest must distinguish a completed non-phylogenetic alpha module from an intentionally skipped phylogenetic figure. A stale or partial PNG must never make a run appear complete.

Touch points: `analysis/utils/metrics.R`, `analysis/02_alpha_diversity.R`, `analysis/utils/config.R`, `analysis/utils/io.R`, `analysis/utils/dependencies.R`, and `renv.lock` if `picante` is selected.

### Phase 3 — make release verification independent

Touch points: `tests/verify_release_run.R`, `tests/testthat/test-alpha-regression.R`, `tests/testthat/test-config.R`, `tests/testthat/test-manifest-schema.R`.

- Read raw abundance/count inputs and independently recompute classified totals, proportions, scalar alpha metrics, and the expected resample depth.
- Validate every long-table metric key, label, parameter, value domain, `Valid` flag, and reason. Reject `NaN`, infinite values, duplicate keys, and unlabeled q orders.
- Check row cardinality (`samples × iterations`, modulo explicit per-sample ineligibility), common depth, seed/provenance, and deterministic reruns.
- Validate the exact metric set in each PNG through the sidecar registry and check dimensions, existence, and stable bytes.
- For phylogenetic outputs, independently verify tree hash, tip-map hash, mapped positive taxa, branch-length/root requirements, and fixture values for PD/PSR/PSE.

### Phase 4 — close transaction and lock recovery

Touch points: `analysis/00_run_pipeline.R`, `analysis/utils/atomic_io.R`, `analysis/utils/ncbi_taxonomy.py`, `tests/testthat/test-transaction-process.R`, `tests/testthat/test-atomic-ownership.R`, and new cross-runtime lock tests.

- Generate one `transaction_id` at run start and include it in taxonomy journals, publication journals, manifest, provenance, candidate cache, and recovery records.
- Use a phase model such as `prepared → candidate_committed → output_published → committed`; do not mark taxonomy `published` until the final manifest contains the same transaction ID and candidate hash.
- Centralize close/recovery logic so locks remain held while rollback runs and while rollback success/failure is durably recorded.
- On rollback or cleanup failure, retain journal and backup, mark `recovery_required`, and stop destructive cleanup. Never delete the only recovery material after a failed restore.
- Make recovery match the exact transaction ID, candidate hash, original hash, and output manifest instead of only an output root/path.
- Prove R/Python lock contention in both directions. Keep `--cache-lock-held` only as an explicit, audited boundary for a lock held by the parent process.

Touch points: `README.md`, `CHANGELOG.md`, `CITATION.cff`, `config.example.yml`, `0.4.6-hardening-patch.md` (supersede or cross-link), and `.github/workflows/ci.yml`.

## 6. Test matrix and release gates

### Metric fixtures

- Equal counts, such as `[1, 1, 1]`: verify `S=3`, `H=log(3)`, `ENS=3`, `D=2/3`, inverse Simpson `=3`, Pielou `=1`, Heip `=1`, Hill N0/N1/N2 `=3`, and the expected equal-abundance Evar/McIntosh behavior.
- A skewed vector, such as `[8, 1, 1]`: compare all closed-form metrics to independently calculated values and ACE/Chao/Fisher to the pinned `vegan` implementation.
- Empty counts, one positive taxon, and total depth one: verify no errors, `NA`/skip reasons where the metric is undefined, and no `NaN`/infinite output.
- Deterministic repeated runs: identical long-table contents and identical PNG hash for identical inputs/configuration.
- Parameterized q values: labels and keys include q; q=0/1/2 crosswalks match richness/ENS/inverse Simpson.

### Phylogenetic fixtures

- A tiny rooted tree with branch lengths and exact tip map: verify Faith PD, PSR, and PSE against hand calculations and pinned `picante` results.
- One-tip and two-tip communities: verify documented PD and PSR/PSE edge rules.
- Missing tree, unrooted tree, absent branch lengths, duplicate tips, duplicate map keys, and an unmapped positive taxon: verify fail/skip status is explicit and no partial phylogenetic figure is emitted.

### Existing audit regressions

- Fresh Linux and Windows Krona checkouts validate identical bytes and hashes.
- Filtered-collision composition fixture: full paths `Bacteria;P1;Shared` and `Bacteria;P2;Shared`, with only the first path selected, must retain the authoritative disambiguated label and pass; a wrong label must fail.
- Mutated Krona HTML fixtures: changed label, changed direct count, missing path, duplicate sibling, altered dataset/sample identity, and incorrect `Unclassified` allocation must all fail.
- Unequal-depth composition fixture: independently recomputed arithmetic sample means must not equal pooled-count proportions when depths differ.
- Transaction crash matrix: failure before candidate commit, after candidate commit, during publication, after publication, during rollback, and during cleanup; recovery materials must remain available whenever closure is incomplete.
- R/Python lock contention fixture: both processes must block or fail deterministically on the same lock contract.

### Release gate

Do not tag `v0.4.6` until all of the following are green at the same final commit:

1. Linux and Windows standard and FAPROTAX CI jobs.
2. Exact vendor inventory/byte hashes from fresh checkouts.
3. Independent release verification for Ambar, synthetic minimap2, zero-classified cohort, unequal-depth composition, and phylogenetic fixtures.
4. All alpha outputs, sidecars, facet contracts, deterministic figure checks, and explicit phylogenetic skip behavior.
5. Offline Krona/browser QA with no network dependency in built-in HTML.
6. Transaction recovery and cross-runtime lock tests.
7. Warning triage recorded, with no warning masking a failed assertion or incomplete recovery.
