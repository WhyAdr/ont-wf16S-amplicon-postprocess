# ONT wf-16S Amplicon Post-Processing Pipeline

Modular, config-driven downstream post-processing, statistical analysis, diversity quantification, and Kraken/Pavian/Krona export for Oxford Nanopore Technologies (ONT) full-length 16S rRNA amplicon sequencing generated by EPI2ME [`wf-16s`](https://github.com/epi2me-labs/wf-16s).

Current pipeline version: **0.4.5**.

The `kreport` pathway also provides an opt-in Krona-compatible TSV export and
offline, self-contained HTML rendering by default. External KronaTools remains
available through an explicit renderer policy.

---

## Architecture & Overview

This repository transforms primary outputs from ONT's Nextflow-based `wf-16s` pipeline into reproducible statistical figures, tables, and Pavian-compatible Kraken reports (`.kreport`). Treat species-level calls and richness estimates as conditional on the upstream classifier, reference database, and abundance threshold—not as independent validation of organism presence.

```
analysis/
├── 00_run_pipeline.R        # Orchestrator & CLI entry point
├── 01_qc_diagnostics.R      # Classification donut, read length distributions, filter diagnostics
├── 02_alpha_diversity.R     # 9 diversity indices, exact analytical rarefaction, resample boxplots
├── 03_beta_diversity.R      # Bray-Curtis, Jaccard, PCoA, PERMANOVA (adonis2) & betadisper
├── 04_taxa_composition.R    # Standardized long-format taxa tables, bars, stacks, heatmap
├── 05_ordination.R          # Hellinger PCA & Bray-Curtis NMDS (cohort mode)
├── 06_shared_taxa.R         # Core/unique taxa by group prevalence, UpSet plot
├── 07_kreport_pavian.R      # Kraken report (.kreport), Krona export, taxonomy provenance
├── 08_faprotax.R            # Opt-in FAPROTAX 1.2.12 taxon-based inference
├── install_packages.R       # Dependency checker & installer (--install)
├── utils/krona_builder.py   # Stdlib-only offline Krona-compatible HTML builder
└── vendor/krona-2.8.1/     # Byte-pinned, unmodified Krona browser assets
```

### Analytical Modes & Gating

The pipeline supports two execution modes:

- **Single-Sample Mode (`single`)**:
  - Focuses on within-sample characteristics: read-length distribution, classification yield, alpha diversity indices, analytical rarefaction curve, rarefaction resamples, taxonomic composition, and Kraken report generation.
  - Multi-sample comparative modules (`03_beta_diversity.R`, `05_ordination.R`, `06_shared_taxa.R`) are **gracefully skipped** with structured records in the manifest.
- **Cohort Mode (`cohort`)**:
  - Requires $\ge 2$ samples and a valid metadata mapping (`SampleID` and `Group`).
  - Executes PCoA ordination, group-level taxonomic stacked bars, composition heatmaps, UpSet plots, and non-parametric group comparisons.
  - **Statistical Gates**:
    - PERMANOVA (`adonis2`) requires at least 2 groups with $\ge 2$ samples per group and residual degrees of freedom. It is paired with `betadisper` homogeneity of multivariate dispersion testing. A warning is issued if any group has $<3$ samples.
    - Optional beta rarefaction stability is marked completed only when the configured minimum success fraction (default `0.50`) of iterations produces valid Procrustes-aligned coordinates; otherwise the diagnostic is skipped with an explicit reason.
    - Non-parametric alpha group tests (Wilcoxon rank-sum or Kruskal-Wallis with Benjamini-Hochberg FDR) require at least 2 groups with $\ge 3$ biological samples each.

## Input Data Contracts

### Supported upstream contract

Version 0.4.5 is validated against the tracked `wf-16s` minimap2 abundance,
assignment, taxonomy-cache, and parameter schemas represented by the Ambar
Ayunda regression fixture. Inputs from historical or future `wf-16s` releases
must satisfy the contracts below; compatibility with arbitrary schemas is not
implied.

### 1. Species Abundance Table (`abundance_table_species.tsv`)
- Tab-delimited table where the first column is `tax`.
- `tax` contains **exactly eight** semicolon-delimited ranks:
  `superkingdom;kingdom;phylum;class;order;family;genus;species`
- Every rank must be non-empty after trimming and must not have leading or
  trailing whitespace; use an explicit label such as `Unknown` when applicable.
- One or more sample columns containing non-negative, integer counts (e.g. `80556` or `80556.0`).
- Synthetic unclassified row: `Unclassified;Unknown;Unknown;Unknown;Unknown;Unknown;Unknown;Unknown`.
- Optional aggregate column `total` must reconcile exactly to the row sum across sample columns.

### 2. Read Assignments (`*.minimap2.assignments.tsv`)
- **Optional** per-sample mapping. If omitted, abundance-only modules proceed normally and read length diagnostics are cleanly skipped.
- Five tab-delimited columns without header:
  1. Status (`C` = aligned/classified, `U` = unaligned/unclassified)
  2. Read ID (unique string)
  3. TaxID (canonical decimal string; TaxID `0` denotes read aligned but failed downstream identity/coverage QC)
  4. Length field (exactly a positive decimal length such as `1481`, or a numeric prefix and positive length such as `0|1481`)
  5. Lineage path (pipe-delimited)
- **Effective Classification**: Defined as `taxid > 0`. Raw status `C` alone overstates classification; reads with status `C` and TaxID `0` are filtered out by upstream reference coverage/identity thresholds.
- Plain-text and `.gz` assignment inputs are read in bounded two-pass chunks.
  Schema validation, physical error line numbers, and the final typed QC data
  frame are preserved while avoiding a whole-file text buffer.

### 3. Producer contract and optional bamstats

- `input.params_json` is required. Version 0.4.5 accepts minimap2, species-rank
  output from the bundled NCBI database sets without custom reference or
  taxonomy overrides.
- `input.wf16s_output_root` is optional. When supplied, the pipeline discovers
  each sample's `bamstats.readstats.tsv.gz` by its internal `sample_name` and
  partitions `C + TaxID 0` reads into identity-only, coverage-only, and
  both-threshold failures.
- Missing optional bamstats produces explicit `NA` fields; a configured invalid
  or ambiguous bamstats contract fails rather than selecting an arbitrary file.

## Analytical Denominators & Metrics

- **Classified-Only Denominator**:
  - Relative abundance for community composition and alpha diversity is computed relative to **classified reads** ($\sum \text{counts}[\text{taxid} > 0]$).
  - Unclassified reads are kept separate and analyzed in the QC diagnostics module.
- **Alpha Diversity Indices**:
  - Observed species richness $S$
  - Chao1 estimated richness
  - Shannon index $H$ and Effective Number of Species ($e^H$)
  - Simpson's index $D$ ($1 - \sum p_i^2$) and Inverse Simpson ($1 / \sum p_i^2$)
  - Pielou's evenness $J = H / \log(S)$
  - Fisher's log-series alpha
  - Berger-Parker dominance ($\max(N_i) / N$)
- **Rarefaction Resamples**:
  - Analytical rarefaction curves are computed with `vegan::rarefy()`.
  - Subsampling iterations with `vegan::rrarefy()` represent **rarefaction resamples without replacement** to assess community sampling sensitivity. They are never presented as independent biological replicates.
- **Richness overview**:
  - `02_richness_overview.tsv` reports positive taxa, singletons, taxa with at
    most 10 reads, and the reads represented by that low-count tail.
  - These summaries remain conditional on upstream filtering, database choice,
    taxonomy, and the abundance threshold; low count alone does not prove artifact.

### Unclassified-read handling by module

| Module | Handling |
|---|---|
| QC | Included in abundance accounting; all assignment reads are shown when assignments exist |
| Alpha diversity | Excluded |
| Beta diversity | Excluded |
| Taxonomic composition | Excluded from rank tables; included in the classification-fraction output |
| Ordination | Excluded |
| Shared taxa | Excluded |
| Kraken/Pavian/Krona | Included as the first `U` line or top-level `Unclassified` contribution and in total-read arithmetic |

### Composition figures and sidecars

This release adds deterministic classified-read-relative composition figures
at phylum, family, and genus ranks. The new vertical stacked bars are written
as matching PNG/TSV pairs:

- `04_phylum_stacked`, `04_family_stacked`, and `04_genus_stacked` for single
  samples or cohorts;
- `04_<rank>_group_mean_stacked` for cohort group means; and
- `04_heatmap_<rank>` for each configured heatmap rank.

The existing single-sample horizontal artifacts (`04a` through `04d`) remain
unchanged. New sidecars retain `TaxonPath` identity, contextual display labels,
sample/group order, stack/row order, denominator validity, and explicit
`IsOther` flags. The all-read `Unclassified` row is not added to these figures;
it remains in `classification_fraction.tsv` and its corresponding plot.

The defaults are:

```yaml
composition:
  stacked_bar_ranks: ["phylum", "family", "genus"]
  stacked_bar_max_taxa: 15
  stacked_bar_min_taxa: 5
  stacked_bar_min_mean_relative: 0.005
  heatmap_rank: null
  heatmap_ranks: ["phylum", "family", "genus"]
  heatmap_top_n_taxa: 10
  heatmap_include_other: true
  heatmap_transform: "log10_relative"
```

For compatibility, a non-null legacy scalar `heatmap_rank` is migrated to a
one-element `heatmap_ranks` vector with one warning. Supplying both keys is an
error; the pipeline never guesses precedence. Heatmap columns are never
clustered. Cohort rows use complete-linkage clustering only when there are at
least two display rows; single-sample rows are abundance-ordered and are not
clustered. A rank with no positive classified abundance produces a structured
`*_skipped.tsv` sidecar instead of a fabricated image.

### FAPROTAX Functional Inference (opt-in)

Request the module explicitly with `--modules faprotax`, or include `faprotax`
in a comma-separated module list. The default module list is unchanged. The
module checks the optional `microeco` dependency only when it is requested and
requires `microeco >= 2.3.0` with its embedded FAPROTAX version exactly
`1.2.12`. This is FAPROTAX 1.2.12 via microeco, not FAPROTAX2-db, PICRUSt2, or
a gene/pathway abundance predictor.

Only positive-count Bacteria and Archaea rows enter the mapping. The canonical
unclassified row and classified non-prokaryotic rows are excluded from mapping
but retained in the explicit read accounting. Pipeline `superkingdom` is
passed to microeco as `Kingdom`; the NCBI `kingdom` rank is intentionally
omitted. Function read counts are the sums of classified taxon counts carrying
each function, with no rarefaction, copy-number correction, or cross-function
renormalization. Functions overlap, so their percentages are independent
fractions and must not be stacked or expected to sum to 100%.

The module writes `08_FAPROTAX/` with the following artifacts:

- `faprotax_function_abundance.tsv`: long `SampleID`, `Function`,
  `FunctionReadCount`, `PctEligibleProkaryoticReads`, `PctClassifiedReads`,
  and `PctTotalReads` table. Each percentage uses the denominator named in its
  column; a zero eligible denominator yields zero percent.
- `faprotax_mapping_coverage.tsv`: per-sample `TotalReads`,
  `UnclassifiedReads`, `ClassifiedReads`, `EligibleProkaryoticReads`,
  `ExcludedNonProkaryoticClassifiedReads`, `FunctionMappedReads`,
  `FunctionUnmappedEligibleReads`, `EligibleProkaryoticTaxa`, and
  `FunctionMappedTaxa`. The equations are
  `ClassifiedReads + UnclassifiedReads = TotalReads`,
  `EligibleProkaryoticReads + ExcludedNonProkaryoticClassifiedReads = ClassifiedReads`,
  and `FunctionMappedReads + FunctionUnmappedEligibleReads = EligibleProkaryoticReads`.
  `FunctionMappedReads` counts each eligible read once when its taxon has at
  least one function; it is not the sum across overlapping functions.
  Every function count is bounded by `0 <= FunctionReadCount <=
  EligibleProkaryoticReads` for its sample.
- `faprotax_taxon_function_assignments.tsv`: positive mappings with stable
  `FeatureID` values and the original `TaxonPath`.
- `faprotax_top_functions.png`: independent bars faceted by sample for the
  configured top functions; it is not a compositional stack.
- `faprotax_provenance.json`: package/database versions, method, source,
  denominator definitions, input filtering, and the overlap warning.

If no positive-count Bacteria or Archaea rows exist, the module writes only
`faprotax_skipped.tsv` and records a structured `skipped` module result. A
missing/incompatible microeco installation or embedded database version is a
failure, not a skip.

These are taxon-based functional assignments/inference. They do not establish
gene presence, pathway completeness, expression, or activity. Cite the
original database/software paper: [Louca et al. (2016)](https://doi.org/10.1126/science.aaf4507).
The tracked-fixture comparison with the official `collapse_table.py` workflow
is recorded in [faprotax1.2.12-concordance-review.md](faprotax1.2.12-concordance-review.md);
the two engines must not be treated as byte-for-byte equivalent.

## Kraken Report & Pavian Interoperability

- Generates standard 6-column `.kreport` files directly from the abundance tree:
  1. Percentage of total reads rooted at this clade
  2. Number of reads in clade (direct + descendants)
  3. Number of reads assigned directly to taxon
  4. Rank code: `U`, `R`, `D`, `K`, `P`, `C`, `O`, `F`, `G`, `S` (Standard Kraken rank codes; kingdom is `K`)
  5. NCBI Taxonomy ID
  6. Indented scientific name (2 spaces per depth level)
- **NCBI Taxonomy Resolution**:
  - Offline default (`network_mode: cache_only`): resolves TaxIDs using local `taxonomy_cache.json` without internet requests.
  - Assignment-derived TaxIDs are written to a run-local resolved cache; an offline run does not mutate the configured source cache.
  - Opt-in refresh (`--refresh-taxonomy`): queries NCBI Entrez E-utilities with bounded exponential backoff, rate pacing, and atomic cache file replacement.
  - Unresolved and conflicting mappings are exported explicitly. Conflicting assignment mappings retain the modal TaxID (minimum numeric TaxID on a tie) for backward-compatible Kreport output, but are labeled `Conflicted`/`assignment_conflict`, emit a run warning, and must not be treated as authoritative without review. Named nodes with TaxID `0` should be resolved before treating the report as taxonomy-complete in Pavian.
  - The tracked cache-only reference run intentionally reports **46 unresolved taxonomy nodes** and **26 conflicting lineage-to-TaxID mappings**. These diagnostics are surfaced rather than silently discarded.
- **Interactive Sankey Visualization**:
  - Generated `.kreport` files can be uploaded to [Pavian](https://fbreitwieser.shinyapps.io/pavian/) for interactive Sankey and sunburst diagrams.

### Krona export (opt-in)

Krona export is an extension of the `kreport` module and does not add a
separate module name. Enable it with either the CLI switch or YAML:

```bash
Rscript analysis/00_run_pipeline.R \
  --config config.yml \
  --modules kreport \
  --krona \
  --overwrite
```

```yaml
krona:
  enabled: true
  render_html: true
  html_renderer: "builtin"  # builtin, kronatools, or auto
  executable: "ktImportText"
```

For each selected sample, R always writes a portable
`07_Kreport/krona/<sample>.krona.tsv` in the tab-delimited lineage format
accepted by KronaTools `ktImportText`. When `render_html: true`, the default
`html_renderer: builtin` uses `analysis/utils/krona_builder.py`; no Perl or
KronaTools installation is required. It writes a deterministic, standalone
`<sample>.krona.html` containing the Krona-compatible XML, JavaScript, and
image resources. `html_renderer: kronatools` is strict and fails if the
configured executable is unavailable. `html_renderer: auto` uses an available
external executable and otherwise falls back to the builtin renderer. Set
`render_html: false` to retain TSV/provenance only.

The vendored Krona 2.8.1 browser files are unmodified and SHA-256 pinned in
`analysis/vendor/krona-2.8.1/SOURCE.json`; the wrapper is described as
Krona-compatible, not as official Krona software. The module writes
`07_Kreport/krona/krona_provenance.json` with renderer policy/version, vendor
manifest hashes, HTML status, and exact read-accounting reconciliation.

Krona magnitudes use direct positive-count taxonomy rows plus one explicit
top-level `Unclassified` contribution when applicable. Ancestor clade counts
are not emitted separately, and Krona generates its own root. The output is a
visualization of the classifier-conditioned abundance table, not independent
taxonomic validation.

## Quickstart

`config.yml` is the tracked Ambar Ayunda regression demonstration.
`config.example.yml` is a copy-and-edit template pre-populated for that
single-sample demonstration. Give cohort projects their own abundance table,
metadata, assignment mapping, and a fresh output directory.

### 1. Audit Dependencies

On Linux, the locked `igraph` binary also requires the GLPK runtime library
(`libglpk40` on the Ubuntu release runner).

```bash
# Check core installed packages (exits non-zero if missing)
Rscript analysis/install_packages.R

# Install missing core packages from CRAN
Rscript analysis/install_packages.R --install

# Check optional module dependencies (e.g. FAPROTAX / microeco)
Rscript analysis/install_packages.R --modules faprotax

# Install optional module dependencies from CRAN
Rscript analysis/install_packages.R --install --modules faprotax

# Audit all dependencies including optional modules
Rscript analysis/install_packages.R --all
```

### 2. Zero-Mutation Validation Run
```bash
Rscript analysis/00_run_pipeline.R --config config.yml --validate-only
```

### 3. Execute Full Pipeline
```bash
# Run pipeline with default config (writes to output/)
Rscript analysis/00_run_pipeline.R --config config.yml

# Override output directory and allow overwrite
Rscript analysis/00_run_pipeline.R --config config.yml --output-dir output --overwrite
```

Use a new output root for publication runs. A non-empty output root may only be
reused with `--overwrite` when it contains a valid pipeline-owned manifest;
the rerun is staged transactionally and replaces the complete owned product set,
while unrelated files are preserved. Normal publication runs also require a
synchronized `renv.lock` environment and a clean maintained source tree. The
development-only `--allow-unlocked` and `--allow-dirty` flags record the
exception in provenance.

### Cohort sample identity

For a cohort, the same sample identifiers must appear in all applicable inputs:

```text
abundance columns:  Sample_A, Sample_B
metadata SampleID:  Sample_A, Sample_B
assignment keys:    Sample_A, Sample_B
```

Set `mode: cohort`, provide metadata with unique `SampleID` and non-empty
`Group` columns, and ensure those IDs match the selected abundance columns
exactly. `metadata.example.tsv` demonstrates the metadata format only; it is
not paired with the tracked one-sample abundance fixture.

### Validation

```bash
Rscript analysis/install_packages.R --restore
Rscript -e "files <- list.files('analysis', pattern='[.]R$', recursive=TRUE, full.names=TRUE); invisible(lapply(files, parse))"
python -m compileall -q analysis tests
Rscript tests/testthat.R
python -m unittest -v tests/test_ncbi_taxonomy.py tests/test_check_committed_whitespace.py
Rscript analysis/00_run_pipeline.R --config config.yml --validate-only
```

The test suite creates a temporary synthetic cohort at runtime to verify
software behavior only; no biologically validated cohort dataset is included.
The committed `renv.lock` pins the R 4.5.3 package graph, including test tooling
and `microeco`; use `analysis/install_packages.R --restore` before release or
publication runs. The lock covers this post-processing environment, not the upstream
`wf-16s` workflow, ONT basecaller, reference database archive, or optional
KronaTools executable.

### Run-manifest schema v2

Version 0.4.5 maintains manifest schema v2 (revision 2) and its machine-readable shape
contract while introducing strict artifact accounting, SHA-256 and byte-size digests for every owned
product, explicit preserved unowned output tracking, and physical output census verification.
Cardinality-dependent fields such as samples, requested modules, package versions, input
collections, module outputs/warnings, artifacts, and Krona provenance samples are always
JSON arrays, including zero and one item. Failed fail-fast runs retain later
requested modules as `not_run` records with null execution timestamps. Every v2
manifest records whether the environment is locked, the SHA-256 of the
repository `renv.lock` used for the run, the supplied configuration file's
SHA-256 and byte size, and available package identity metadata from the lockfile
and installed `DESCRIPTION` files.

Publication safety includes exclusive file locking (`.wf16s_output.lock`) preventing concurrent
pipeline execution against the same output root, isolated per-module private staging directories,
and hashed sibling transaction journals (`.*.wf16s_journal.json`) that guarantee deterministic
rollback or forward-recovery across aborted writes. Online taxonomy refresh is computed into the
run-local resolved cache first, then commits the shared source cache under an inter-process lock;
a sibling taxonomy transaction journal and hash comparisons restore or forward-recover an interrupted
commit without overwriting an unrelated cache revision. True zero-mutation
`--validate-only` checks perform in-memory AST syntax validation without writing bytecode or touch files.

The tracked assignment fixture retains its typed-column digest under the streamed
reader. On this Windows R 4.5.3 host, the manual 250,000-row benchmark completed
in 13.33 seconds, returned a 30.53 MiB data frame, and observed a 343.27 MiB
process peak working set. Run `Rscript tests/benchmark_assignment_parser.R --rows=250000`
on each target host for local performance evidence.

### Command-Line Options
| Option | Description |
|---|---|
| `-c, --config PATH` | Path to YAML config (default: `config.yml`) |
| `-o, --output-dir PATH` | Override output directory |
| `-m, --modules LIST` | Comma-separated modules: `qc,alpha,beta,composition,ordination,shared,kreport,faprotax` |
| `--validate-only` | Run the same requested-module preflight checks without writing to disk |
| `--keep-going` | Continue executing remaining modules if one fails |
| `--refresh-taxonomy` | Enable online NCBI queries to resolve missing TaxIDs |
| `--online-preflight` | Permit refresh-mode preflight to contact NCBI (otherwise no network calls are made) |
| `--allow-unlocked` | Development-only escape hatch for a missing/mismatched lock (recorded as unlocked) |
| `--allow-dirty` | Development-only escape hatch for maintained source changes (recorded as dirty) |
| `--krona` | Enable Krona TSV export and builtin or policy-selected HTML rendering (requires `kreport`) |
| `--overwrite` | Replace the complete set of pipeline-owned products in a validated output root |

## Release Scope

Version 0.4.5 covers validated NCBI/minimap2/species parsing, exact read accounting,
single-sample summaries, deterministic multi-rank classified-read composition
figures and heatmaps, synthetically tested cohort modules, offline-by-default
taxonomy resolution, Pavian-ready Kraken reports, opt-in Krona-compatible TSV
export with a builtin offline standalone HTML renderer, and an opt-in FAPROTAX
1.2.12 functional inference module (via locked `microeco 2.3.0`). It also includes
manifest schema v2 revision 2, bounded assignment parsing, physical output census
verification, transaction journals, and multi-process cache locking. The project does
not include differential abundance, phylogenetic UniFrac, FAPROTAX2-db,
PICRUSt2, automatic Pavian HTML export, or biological validation of cohort
statistics or species-level calls. The `0.4.4` version number was intentionally
reserved/skipped; this release target is therefore `0.4.5`.
